# The flow look: Program and Run as a left-to-right node flow

Status: design, 4 Nov 2026, from the user's reference (a behaviour-flow editor: nodes with coloured headers, Success
and Failure ports wired to the next node or to a Fail terminal, nested containers as grey boxes, fields inside the
nodes). It changes how the mission graph looks and reads, not the mission files, the ops or the server.

## 1. What the user asked for

- The Program editor looks like the reference: a flow from left to right, a Start node, nodes with a coloured header
  that names the node and its kind, **done** and **fail** ports on the right edge, wires to the next node, a Fail
  terminal where a failure ends the mission, Succeed at the end, containers for the blocks.
- The Run tab gets a **simplified** version of the same look: the same nodes and containers, no ports, no terminals,
  the state in colour, the running node open.
- **As little text as possible.** A node reads by its header word and its colour; the instruction sentence moves to
  the panel (editor) and the pop-up (Run). The mission files are not touched: the sentences stay there for the
  planner and the pop-up.

## 2. Node anatomy

A node (`.fl-node`) is a dark body (`--surface-card`, 1px `--border`, 6px radius) with:

- a **header strip** in the kind colour: the **name** (left, 600, 14px) and the **kind word** (right, 11px, 80%);
- a **body** with at most two **fields** in mono, `key value` (`to  bin_1/place`); none when the step has no main
  argument; on a phone no fields;
- an **input port** on the left edge (a 10px dot, `--border-strong`), and in the editor two **output ports** on the
  right edge: **done** (top, `--text-muted`, filled lime while the wire runs) and **fail** (below, coral); their
  words sit inside the body at the right edge in 10px. The Run view draws no ports.

Sizes: editor 220 × 64 (header 24, body 40), phone 168 × 52; Run 160 × 48, phone 132 × 44.

### Names (the text rule)

| Node | Name | Fields |
|---|---|---|
| skill step with an `id` | the id, humanised (`to_shelf` → `To shelf`) | the main argument (`to`, `hands`+`action`, `seconds`, the first of the rest) |
| skill step without an id | the skill name (`Move`, `Grip`, `Wait`, `Hold level`) | as above |
| include | the mission name humanised (`pick_frame` → `Pick frame`) | the `with` values, up to two |
| group / repeat / parallel block | its id humanised, else `Group` / `Repeat` / `Parallel` | repeat: its rule (`×3`, `while next_stack`); parallel: `join first` only when set |
| lane | its id humanised, else `Lane 1`, `Lane 2` | none |
| Start | `Start` | none |
| Succeed terminal | `Done` | none |
| Fail terminal | `Fail` | the rule word when it is not `abort` from the defaults: nothing for the plain case |
| retry node | `Retry` | `×n` |
| replan badge | `Replan` | `≤ n` when max_replans is set |

The instruction sentence is the node's `title` (tooltip), the panel's first field (editor) and the pop-up's text (Run).
Kind words: `Action`, `Mission` (an include), `Group`, `Repeat`, `Parallel`, `Lane`, `Start`, `End`, `Fail`, `Rule`.
No other words on the canvas: no "Click a step", no port words in Run, no counts in headers (the count lives in the
stack node of a closed frame as today).

## 3. Colours (tokens, all in `:root`, contrast checked at 4.5:1 for the header text)

| Token | Value | Header of | Text on it |
|---|---|---|---|
| kind colours `--kind-*` | as today | an action step (by its kind of motion: drive, arm, grip, wait, other) | `--on-fill` |
| `--brand` | `#3d3dff` | an include (Mission) and a group | `--on-brand` |
| `--warn` | `#ffc95c` | a repeat and a parallel block, their lanes a 60% tint | `--on-fill` |
| `--flow-rule` | `#c98a3a` | retry and replan rule nodes | `--on-fill` |
| `--flow-end` | `#1d7a4c` | Start and Done | `#ffffff` |
| `--flow-fail` | `#8a1f2e` | a Fail terminal | `#ffffff` |

State in Run: the running node's whole body takes the kind fill with a lime ring (as today), done nodes keep the
header and dim the body to 70%, pending nodes are as drawn, a failed node gets a coral outline, paused amber, skipped
a dashed outline. The selected node in the editor: a 2px brand outline; a problem: a red left bar as today.

Wires: 2px, `--text-muted`; the editor's fail wires coral at 70%; the Run view's run-so-far wire lime, the running
one flowing (as today), pending dotted. Bezier S-curves between ports (`graphWire` with a horizontal bend). The
canvas keeps the dotted grid.

## 4. Layout

- **Main axis left to right**, the Start node at the left, Done at the right. A node's done port wires to the next
  node's input. The last node's done wires to Done; with `loop: forever` (or a count) it wires back to Start along
  the bottom of the flow, the loop words on the wire's middle (`forever`, `×5`): the only words on a wire.
- **Failure routes (editor only):**
  - `abort` (also the mission default): a Fail terminal 120 × 40 under the node, its input from the node's fail port.
    The mission's defaults make most steps `abort`: every such step gets its own terminal, as in the reference, in
    one row under the flow so the flow line stays straight.
  - `skip`: the fail port wires (dashed coral) into the next node's input.
  - `retry`: a Retry rule node (100 × 36) under the node, its output back into the node's input (a small loop).
  - `replan`: the fail port wires back (coral, along the bottom, under the terminals' row) to the input of the
    replan_from node, a Replan rule node on that wire's middle (`≤ n`). Drag from the fail port to a node sets it as
    today; a click on a fail port or on a Fail/Retry/Replan node opens the rule menu of its step.
  - The Run view draws none of this but the replan wire (thin, coral, no node), as today.
- **Containers** (`.fl-box`): a block is a translucent box (`--surface-field` at 60%, 1px `--border`, 8px radius) with a
  title bar (28px: a 4px strip in the kind colour at the left, the name, the kind word, and at the right the open or
  close chevron; in the editor the chevron also selects the block). Children run left to right inside, 16px padding.
  A **parallel** box holds its lanes as rows, each lane a thinner box (tinted header) with its own flow; the block's
  input fans to every lane's first node, every lane's last done joins into the block's done port (drawn on the box's
  right edge, with a fail port under it). A **repeat** box has a return wire from its right edge to its left edge
  along its bottom, its rule on the box title (field), no words on the wire. A **group** box has only the title. An
  **include** collapsed is one node (`Mission` header, brand) with an Open chevron; opened it is a box like a group
  with its children at 70% and not editable (as today). A closed block is one stack node as today (cards behind).
  An empty box keeps a muted dot so the "+" spots have a place.
- **"+" spots** sit on every wire's middle and at the end of every open box, as today. Node drag onto a wire,
  box select, Shift+A, the palette and the panel work unchanged; only the geometry and the drawing change.
- **Phone (≤ 600px):** the same flow, smaller nodes, no fields; the canvas scrolls horizontally (not the page) and
  opens scrolled to the selected or first node; the panel under the canvas as today. The Run view on a phone is the
  same flow in a horizontally scrolling strip, the running node centred.

## 5. Run tab (simplified)

The compact graph is the same flow without ports, terminals, rule nodes or words on wires: Start, the nodes, boxes
for the blocks (the one with the running step open, the others closed as stack nodes as today), Done. Headers carry
the name only (no kind word, except on a box title). The only field shown is the running node's main argument.
Everything else the Run view does today stays: the pop-up and the phone sheet on a click, the legend, the live
state colours, the loop badge, the bands under the robot.

## 6. Out of scope

The mission files' instruction sentences (unchanged), the ops format, the server, the Teach/Robot/Record/Log tabs,
a free canvas.
